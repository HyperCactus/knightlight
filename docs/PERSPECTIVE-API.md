# Perspective challenges

The [OpenAPI contract](perspective.openapi.json) describes these additive, unversioned endpoints; future same-repository changes preserve existing fields. The same-repository frontend uses these additive local endpoints. Existing review responses are unchanged. They inherit the app’s localhost and origin checks. No credentials or external service are involved.

`GET /api/reviews/{id}/perspectives` returns `200 {items: Challenge[], next_cursor: null}`. The list is strictly bounded to two entries; there is no additional page. Each challenge has `ply` (the one-based reviewed move after which the opponent responds), `kind` (`punish` or `defend`), `fen`, `side`, `intro`, and `objective`. Answers and engine lines are deliberately omitted. Analysis is cached in memory and recomputed safely after eviction or restart. Missing games return 404, reviews still being analyzed return 409, and unavailable engine analysis returns 503. A game can legitimately have an empty list. Game changes invalidate plans; analysis finishing for an older revision returns 409 rather than publishing a stale challenge.

`POST /api/reviews/{id}/perspectives/{ply}/moves` takes `{uci: string}` for a response or `{reveal: true}` for the engine response. It returns `200 {accepted, revealed, board, feedback}`. `board` has the same fields as `/api/board`; `feedback` uses the existing `ReviewMove` schema including legal visual evidence and short continuations. Legal responses are evaluated independently, so equivalent strong alternatives can be accepted. Invalid or illegal moves return 400; an unselected move or missing game returns 404; engine failures return 503. Errors use the app’s existing `{error: {message}}` envelope.

Attempts are stateless and safe to retry. They never write game moves, learner examples, practice cards, XP or ratings. Client cancellation does not have to cancel the engine process: the response is harmless, and the frontend checks challenge identity before touching its board. Both position and orientation are restored when the user skips, steps, changes game, navigates away, or interrupts an explanation.

Selection first ranks meaningful mistakes and pressure after strong moves. Fresh depth-15 MultiPV analysis checks up to four candidates, with depth-18 verification for ambiguity and risky exchanges. The best response must retain a playable position and stand apart from weaker alternatives. Defensive lessons receive a stable preference in roughly one game in three when available. The cap is one challenge below 64 plies and two otherwise, with a 16-ply gap and no duplicate board positions. Ordinary review starts immediately while this optional analysis runs.

The browser keeps an independent `seen` set for automatic challenges during the session; explicit invitations may be replayed. The setting `reviewChallenges` defaults to true and controls automatic preparation and invitations. The controller holds the review clock while the board is interactive. Clicks and drags use the existing promotion picker, keyed pieces and move animations. Narration and visual explanations share the existing local voice and diagram system. The challenge card occupies the fixed coach slot; it never inserts a panel above the board.
