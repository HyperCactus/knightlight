# Local API

The same-repository browser is the only intended client. The server listens on loopback and permits only localhost Host headers and same-origin browser calls. No authentication is used; trusted processes on the computer can access it. This is an additive local API, not a versioned public service. JSON requests are subject to Axum's body limit, with smaller domain limits below. Errors have `{ "error": { "message": "…" } }` for application handlers. Axum may return plain-text extraction errors for malformed JSON/path types.

| Endpoint | Request | Response |
|---|---|---|
| `GET /api/data` | — | Local library snapshot, puzzles, import progress. Existing snapshot contract for this small local collection. |
| `GET /api/profile` | — | Learned sample count, average loss, date-weighted practice/adaptive ratings, rating sample count and 14-day half-life, rated bot game count, rating history, category statistics, opening/voice status. |
| `POST /api/board` | `{fen}` | Legal moves, side to move, check and terminal state. |
| `POST /api/move` | `{fen,from,to,promotion?,history?}` | Validated next board; 400 on illegal moves or inconsistent history. Full history enables threefold repetition. |
| `POST /api/bot` | `{fen,rating?,style?,moves?,session_id?}` | Legal sampled move, rating/style, model source, warm inference time, opening membership. Rating 400–2400; omit for adaptation. Legacy `skill` 0–20 is still accepted. A session ID makes varied style stable; a supplied move history must match FEN. |
| `POST /api/coach` | `{fen,uci?,learn?}` | Move grade, evaluations, evidence-based explanation, best/reply lines, and structured `evidence` diagrams. Each diagram includes optional `before` FEN and `uci` move metadata for contextual animation. Without uci, explains the preferred move. `learn` updates the local model with position/move deduplication. |
| `GET /api/reviews/{index}` | — | Full cached review; 202 while analyzing; 404 for an unknown game. |
| `POST /api/opening` | `{moves}` | Longest matching named opening and up to six continuations. At most 600 plies. Counts indicate named variations, not games. |
| `POST /api/attempts` | `{id,solved}` | Records a puzzle attempt and updates priority. Each request is an attempt; do not automatically retry. |
| `POST /api/games` | `{white,black,result,date,event,moves,session_id,opponent_rating?,played_at?,analyze?}` | Saved practice-game index and weighted practice rating. Upserts by session ID; validates up to 600 legal plies and RFC3339 play timestamp. `analyze:false` defers unfinished-game analysis during autosaving; default true. Completed results create one Elo sample per session. Stale shorter autosaves cannot replace newer moves. A different result for an already rated session returns 409. |
| `POST /api/imports` | `{pgn}` | `{imported,duplicates,rejected,indices}`. Up to 128 MB of PGN, 100,000 games/file, 600 plies/game. Each main line is validated; illegal games are rejected whole. Supports comments/variations during parsing; retains headers/main line. Custom start positions/variants are rejected. No valid games returns 400. Imports persist immediately, update the weighted score, and queue analysis. |
| `GET /api/games/pgn` | — | Attachment containing all games as standard PGN, including bot games and their rating/date/session metadata. |
| `GET /api/games/{index}/pgn` | — | Selected game as a PGN attachment; 404 for unknown index. |
| `GET /api/practice` | — | Card schedules, due count, up to ten recommended position IDs, theme mastery, seven activity days, streak, XP/level, today’s XP, distinct daily position count, and achievement states. Read-only. |
| `POST /api/drills` | `{id}` | Creates a bounded continuation exercise from an existing personal/public position; returns session, revision, board, best move, objective and evidence. |
| `POST /api/drills/{session}/moves` | `{uci,revision,request_id}` | Checks a legal attempt, returns accepted/complete flags, player and defensive reply steps, updated board/revision, feedback, a move assessment, prediction choices, and evidence. Completion includes a recall question and `xp_earned` (zero for a position already rewarded that day). A repeated request_id returns the saved response. 409 for a stale revision/completed session; 404 if expired. |
| `POST /api/drills/{session}/help` | `{kind:"hint"|"reveal"}` | Marks guidance; returns best move, line and evidence. Reveal records a guided review once. Guidance cannot earn unaided mastery. |
| `POST /api/drills/{session}/reflection` | `{answer}` | Checks a listed recall answer after completion. Only the first answer changes recall counts; an incorrect answer resets the review to tomorrow. 409 before completion. |
| `POST /api/speech` | `{text,voice?}` | `{url,engine,voice,cached,synthesis_ms}` for a locally synthesized WAV. Voice defaults to `af_heart`; allowlisted `af_heart`, `am_michael`, `bf_emma`, `piper`. Other voices return 400. Speed and volume are applied by the browser, so cached synthesis is shared across speed settings. 1–1800 bytes; serialized worker and text cache. 503 if unavailable or busy. |

The import route allows a 256 MB JSON body to accommodate escaping, then enforces a 128 MB decoded PGN limit and 100,000 games per file. Rating weights use dates played (RFC3339 timestamps interpreted in Brisbane, otherwise the PGN Date tag), with a 14-day exponential half-life. Unknown dates, unfinished games, and games without usable rating samples are excluded from rating calculations, not from history.

At most 128 in-memory drill sessions are retained; a server restart expires them while preserving schedules. The full offline bank contains 100,000 distinct public positions; a small embedded pack is available as a fallback.

Engine work for live coach/bot/drills is limited to two simultaneous jobs, with a 30-second engine output timeout. Background game reviews run serially and are cached. Speech has a 45-second response timeout. The persistent CPU worker uses local Kokoro/Piper assets and never downloads during synthesis. Reward state is persisted in practice.json; one completion and one correct-recall reward per position/day prevent retry farming. Maia has a 40-second response deadline and a serialized persistent worker; its model is loaded from local files with Hugging Face offline mode enabled. No uploaded text, filename, or position is interpolated into a shell command. The static server serves `static/` and the generated audio directory only.

Autosave responses include the canonical `game`, its `index`, `practice_rating`, `ready`, `progress`, and `total`, so clients can update one library entry without fetching the full snapshot. Persistent history changes are serialized and run outside the async request worker and shared library lock. Practice sessions use individual atomic records under `data/sessions/`; the legacy archive remains readable. Older snapshots ignored by the save guard return the current canonical game.

Each review move has `review_pace: {multiplier, complexity, signals}`. The backend derives this teaching heuristic from the move's legal board state, evaluation change, forcing/tactical ideas, existing evidence, and the previous move for recaptures. `multiplier` is bounded to 0.5–2.0 relative to the user's base reading pause, `complexity` is 0–100, and `signals` supplies short diagnostic reasons. Cached reviews recompute it on load without extra engine searches. The frontend applies it after animation and narration and preserves reading time when paused. Missing metadata falls back to the chosen base pace.
